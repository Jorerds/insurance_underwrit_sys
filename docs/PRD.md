## 1. 项目背景与目标

### 1.1 背景

某医疗保险公司需要建设一套核保系统，对客户投保申请进行健康告知审核与风险评估，自动或人工做出承保决定（是否承保、以何种条件承保），并输出核保结论。

### 1.2 目标

- 实现投保申请全流程线上化：投保 → 健康告知 → 智能核保 → （人工核保 / 体检）→ 核保结论 → （复议）→ 承保。
- 通过规则引擎自动处理标准案件，复杂案件转人工核保，提升核保效率。
- 提供核保数据统计看板，支撑业务决策。

### 1.3 非目标（本期不做）

- 支付、保单生成、理赔等承保后流程。
- 对接外部渠道（银保通、互联网平台等）。
- 对接医院/体检机构系统的自动数据回传（本期体检结果由机构人工录入）。

## 2. 用户角色与权限（RBAC）

| 角色 | 标识 | 核心职责 | 数据范围 |
| --- | --- | --- | --- |
| 客户 | `customer` | 填写投保申请、健康告知；查看核保结论；发起复议 | 仅本人申请 |
| 核保员 | `underwriter` | 处理人工核保案件、登记体检、出具核保结论 | 全部核保案件 |
| 体检机构 | `exam_center` | 录入/上传客户体检结果 | 仅本机构相关体检单 |
| 核保主管 | `supervisor` | 复核人工核保结论；处理复议案件 | 全部核保案件 |

**权限规则：**

- 不同角色登录后展示不同菜单。
- 核保主管对人工核保结论有**复核**环节：核保员出具结论后，主管复核通过则结论生效；复核退回则案件回到人工核保状态。
- 复议由核保主管处理，复议结论为**最终结论**，不可再次复议。

---

## 3. 业务流程

### 3.1 主流程

```
客户投保 ──> 健康告知问卷 ──> 智能核保（规则引擎）
                                  │
              ┌───────────────────┼───────────────────┐
           标体/加费/除外       需补充体检            复杂/高风险案件
              │                    │                    │
         直接出结论          登记体检机构/项目       转人工核保
              │                    │               （核保员→主管复核）
              │               机构录入结果              │
              │                    │                    │
              └──────────> 核保结论生效 <────────────────┘
                                  │
                    客户有异议 ──> 核保复议（主管处理）
                                  │
                              最终结论
```

### 3.2 核保结论类型（枚举）

| 结论代码 | 结论名称 | 说明 |
| --- | --- | --- |
| `STANDARD` | 标体承保 | 按标准费率承保 |
| `EXTRA` | 加费承保 | 在标准费率基础上加费承保 |
| `EXCLUSION` | 除外承保 | 承保但除外特定疾病/部位责任 |
| `POSTPONE` | 延期 | 暂不接受，建议一定期限后重新投保 |
| `DECLINE` | 拒保 | 拒绝承保 |

## 4. 功能需求

### 4.1 投保申请（客户）

- 客户登录后新建投保申请，填写：
  - **基本信息**：姓名、性别、出生日期、证件类型/号码、联系电话、职业、投保计划（险种、保额、保障期限、缴费方式）。
  - **健康告知**：按所投险种展示健康告知问卷（见 4.2）。
  - **既往病史**：既往确诊疾病、手术、住院记录（疾病名称、诊断时间、治疗情况）。
  - **家族病史**：直系亲属（父母/兄弟姐妹）遗传性疾病、重大疾病史。
- 申请提交后生成申请单（单号自动生成，规则如 `UA+yyyyMMdd+6位序号`），状态为"待核保"。
- 客户可查看本人申请列表及状态。

**申请单状态机：**

```
待核保(PENDING) ──> 智能核保中(AUTO_UNDERWRITING) ──> 待体检(EXAM_REQUIRED)
       │                    │                              │
       │                    ├─> 已出结论(DECIDED) <────────┘
       │                    └─> 待人工核保(MANUAL_REQUIRED) ──> 复核中(REVIEWING) ──> 已出结论(DECIDED)
       │                                                        （复核退回则回到待人工核保）
已出结论(DECIDED) ──> 复议中(RECONSIDERING) ──> 复议完成(RECONSIDERED，最终结论)
```

### 4.2 告知问卷配置

- 告知问卷**按险种配置**：每个险种维护一套健康告知题目。
- 题目类型：
  - 是/否题：客户选择"是"时，必须填写**详细说明**（何时、何地、诊断、治疗情况）。
  - 详细说明题：自由文本。
- 题目配置项：题干、排序、是否必答、是否为"风险题"（答"是"即触发风险的题目）。
- 题目支持启停，停用的题目不在新申请中展示。

### 4.3 智能核保

- 客户提交申请后，系统自动执行评估：
  - 遍历问卷中所有"风险题"，若客户对任一风险题回答"是"，则结合**核保规则**评估。
- **核保规则**（可由业务配置，核心要素）：
  - 规则条件：基于险种 + 风险题/既往病史/家族病史关键词匹配（如"BMI 超标""高血压""糖尿病"）。
  - 规则动作：输出结论建议（标体/加费/除外/延期/拒保）及加费比例、除外责任描述。
  - 多条规则命中时取最严重结论（严重度排序：拒保 > 延期 > 除外 > 加费 > 标体）。
- 自动评估结果：
  - 命中明确规则 → 自动出具结论（标体/加费/除外）。
  - 命中"需人工判断"标记的规则、或规则冲突、或评分超过人工阈值 → 转**待人工核保**。
  - 规则要求体检（如年龄 ≥ N 且保额 ≥ M）→ 转**待体检**，体检结果回来后再评估。

### 4.4 人工核保（核保员）

- 待人工核保案件列表：展示申请单概要（客户、险种、保额、触发转人工的原因）。
- 案件详情页：完整展示客户基本信息、问卷作答、既往病史、家族病史、体检结果（如有）、智能核保建议及命中的规则。
- 核保员出具结论：选择结论类型（5 种），填写：
  - 加费承保：加费比例（%）。
  - 除外承保：除外责任描述。
  - 延期：建议延期时长。
  - 拒保/延期：拒保/延期理由（必填）。
- 结论提交后进入**复核中**，由核保主管复核。

### 4.5 核保复核（核保主管）

- 复核列表：展示待复核的人工核保结论。
- 复核操作：
  - **通过**：结论生效，申请单状态变为"已出结论"。
  - **退回**：填写退回原因，案件回到"待人工核保"，核保员修改后重新提交。
- 复核记录留痕（复核人、复核时间、意见）。

### 4.6 体检管理

- 体检触发：智能核保规则要求，或人工核保要求补充体检。
- 核保员创建体检单：选择**体检机构**、**体检项目清单**（如血常规、心电图、B 超等，可配置）、备注。
- 体检单状态：待体检 → 结果已录入 → 已完成。
- 体检机构登录后录入/上传体检结果（支持逐项录入结果值 + 结论描述；附件上传可后置）。
- 体检结果录入完成后，案件回到智能/人工核保继续评估。
- 体检机构仅能看到与本机构关联的体检单。

### 4.7 核保结论

- 结论生成（自动或人工复核通过）后：
  - 生成正式核保结论记录：结论类型、理由说明、加费比例/除外描述/延期时长、出具人（系统/核保员）、出具时间。
  - 客户可在本人申请详情中查看结论。
- 延期/拒保结论必须填写理由说明。

### 4.8 核保复议

- 客户对已出结论有异议，可在结论出具后 **30 天内**发起一次复议，必须填写**复议理由**并可补充材料说明。
- 复议申请后案件状态变为"复议中"，进入核保主管待办。
- 核保主管处理复议：维持原结论 / 变更结论（变更为 5 种结论之一），填写复议意见。
- **复议结论为最终结论**，状态变为"复议完成"，客户可见。
- 每个申请单仅允许发起一次复议。

### 4.9 核保统计（看板）

- 统计维度：
  - **按险种**：核保量、各结论分布、通过率。
  - **按年龄段**（如 0-17 / 18-30 / 31-40 / 41-50 / 51-60 / 60+）：核保量、通过率。
  - **按核保结论**：各结论占比。
  - 通过率定义：`(标体 + 加费 + 除外) / 全部核保量`（即非拒保/延期的占比）。
- 展示形式：统计卡片 + 表格 + 图表（柱状图、饼图），时间范围可筛选（默认近 30 天）。
- 权限：核保员、核保主管可见；客户、体检机构不可见。

### 4.10 报表导出

- 支持将统计结果及案件明细导出为 **Excel（.xlsx）** 和 **CSV**。
- 导出范围受当前用户数据权限约束（客户不可导出）。

### 4.11 登录与权限管理

- 账号密码登录（本期不接入短信/OAuth）。
- 后端基于 RBAC 鉴权：角色 → 菜单权限 + 数据权限。
- 管理员预置（不在本期角色范围内，由初始化脚本创建），用于维护险种、问卷题目、核保规则、体检项目等基础配置。
  - 基础配置管理界面本期以**后台管理页**形式提供（登录管理员角色可见）。

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 智能核保评估响应 < 2s；统计看板查询 < 3s |
| 并发 | 支持 100 在线用户（内部系统量级） |
| 安全 | 密码加盐哈希存储；投保数据属敏感个人信息，传输 HTTPS、落库无额外加密要求；接口按角色鉴权 |
| 审计 | 核保结论、复核、复议、体检结果等关键操作留痕（操作人、时间、前后值） |
| 浏览器 | 支持 Chrome / Edge 最近两个大版本 |
| 语言 | 前端界面与提示信息统一中文 |

## 6. 关键术语

| 术语 | 说明 |
| --- | --- |
| 标体承保 | 按标准费率正常承保 |
| 加费承保 | 费率上浮后承保 |
| 除外承保 | 承保但对特定疾病/部位不承担赔付责任 |
| 延期 | 暂时不予承保，建议未来某时点再投保 |
| 拒保 | 不予承保 |
| 智能核保 | 基于预设规则的自动化核保评估 |
| 人工核保 | 核保员人工审核并出具结论 |

## 7. 附录：已明确的假设（待业务确认）

1. 复核环节仅针对**人工核保结论**；智能核保自动结论直接生效。
2. 复议仅一次、30 天有效期，复议结论为最终结论。
3. 体检机构为独立登录账号，仅能录入本机构体检单结果。
4. 管理员角色由初始化脚本预置，负责险种/问卷/规则/体检项目配置。
5. 通过率 = （标体+加费+除外）/ 核保总量。
