- **来源**：用户手动测试反馈 —— 统计看板导出 Excel/CSV 提示"网络异常，请稍后重试"。

- **根因**：axios 响应拦截器把非 401 错误（含 403 无权限等）笼统报为"网络异常"，误导定位；统计接口要求核保员/主管角色，多角色同浏览器切换导致令牌被覆盖时会触发 403。
- **修复**：拦截器按状态码给出准确提示（403/404/422/500 各有明确文案），console 输出请求 URL 与真实状态码便于诊断。
- **验证**：`npm run build` 通过；后端导出链路复验正常。

## 2026-10-18 缺陷修复：统计导出 404（手动测试发现）

- **来源**：用户手动测试反馈 —— 导出报错，Console 显示真实状态码 404（`/api/v1/stats/export?...`）。
- **根因**：`frontend/src/api/stats.ts` 的 `exportUrl()` 返回了带完整 `/api/v1` 前缀的路径，而 axios 实例 `baseURL` 已是 `/api/v1`，拼接后请求实际发往 `/api/v1/api/v1/stats/export` → 404。此前 curl/Node 模拟均手写单前缀 URL，未走该代码路径，故未复现。
- **复现验证**：双前缀请求返回 404，单前缀返回 401（未带令牌，符合预期），根因实锤。
- **修复**：`exportUrl()` 改为返回相对路径 `/stats/export?...`。
- **验证**：`npm run build` 通过，待用户浏览器复验。
