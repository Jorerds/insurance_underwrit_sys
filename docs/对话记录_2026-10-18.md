# 医疗保险核保系统 —— 开发对话记录

> 备份日期：2026-10-18
> 说明：本文档为开发过程中的对话记录备份，按时间顺序整理，工具执行细节已精简，保留需求、决策、结论与缺陷修复过程。

---

## 1. 需求提出与 PRD 编写

**用户**：介绍了项目背景——某医疗保险公司需要建设核保系统，需求包括：投保申请（基本信息/健康告知/既往病史/家族病史）、告知问卷（按险种配置，是/否/详细说明）、智能核保（标体/加费/除外/拒保，复杂转人工）、人工核保、体检管理、核保结论（标体/加费/除外/延期/拒保）、核保复议（最终结论）、核保统计、RBAC 角色登录（客户/核保员/体检机构/核保主管）、统计报表导出。

**我**：创建了 `docs/PRD.md`，并列出 5 条假设请用户确认：
1. 复核环节仅针对人工核保结论；智能核保自动结论直接生效。
2. 复议仅 1 次、30 天有效期，复议结论为最终结论。
3. 体检机构为独立登录账号，仅能录入本机构体检单结果。
4. 管理员角色由初始化脚本预置，负责险种/问卷/规则/体检项目配置。
5. 通过率 =（标体+加费+除外）÷ 核保总量。

**用户**：确认假设无误，继续技术方案。

## 2. 技术方案

**我**：创建 `docs/技术方案.md`，核心决策：
- 技术栈：Vue3 + Element Plus（zh-cn）+ TailwindCSS + ECharts；FastAPI + SQLAlchemy 2.x + Celery/Redis + MySQL 8 + JWT。
- 规则引擎：`underwriting_rule` 配置表（条件 JSON + 动作 + 优先级），Celery 异步评估。
- 状态机：申请单 8 个状态（PENDING → AUTO_UNDERWRITING → EXAM_REQUIRED / MANUAL_REQUIRED → REVIEWING → DECIDED → RECONSIDERING → RECONSIDERED）。
- 数据库 15 张表设计、REST API 设计、目录结构、7 个里程碑（M1-M7）。

**用户**：方案评审通过，开始开发。

## 5. M3 智能核保

**关键设计决策**（我主动提出）：多规则取最严重采用内置严重度映射（拒保>延期>除外>加费>标体），**不引入技术方案中的 priority 配置字段**——动作枚举本身已表达严重度，少一个字段少一处配错。Celery 骨架就位但 `use_celery=False` 默认同步评估（开发免 Redis）。

完成内容：
- 新增表：underwriting_rule（条件 JSON + 动作 + 启停，product_id 空为通用）、underwriting_result（三来源结论表）。
- 规则引擎：风险题答"是"/病史关键词/家族关键词/年龄/保额任一命中即触发；流转优先级：拒保/延期直接生效 → 体检 → 转人工 → 自动结论；无命中默认标体。
- admin 规则 CRUD + 入参校验；客户详情接口返回已生效结论。
- 前端：核保规则配置页、详情页结论卡片。

过程中解决的问题：同步评估新建全局会话与测试依赖覆盖脱节 → 改为复用调用方会话（Celery 路径仍在任务内自建会话）。

测试：后端 30 用例全部通过（新增 11 个）。

## 6. M4 人工核保与复核

**设计说明**：M3 转人工时命中规则快照未落库，核保员看不到"为什么转人工"——给 application 加 `auto_advice` JSON 列统一留痕。复核针对结论记录操作，退回后旧记录留痕不删，可重新提交新结论。

完成内容：
- 核保员：案件列表、案件详情（评估快照+上次结论+退回意见）、出具结论（5 类，参数校验同规则口径）→ REVIEWING。
- 主管：待复核列表、通过（is_final、DECIDED）、退回（意见必填、回 MANUAL_REQUIRED）。
- 复核通过前客户不可见人工结论。
- 前端：待办列表（状态页签）、案件处理页、复核中心。

过程中解决的问题：退回接口空 comment 在 Pydantic 层 422（测试断言修正）。

测试：后端 42 用例全部通过（新增 12 个）。

## 7. M5 体检管理

**设计说明**：体检结果作为案件资料供核保员参考，不增加规则维度（PRD 只要求登记）；体检单 PENDING → RESULT_ENTERED → DONE；结果回流后重评跳过体检类规则。

完成内容：
- 新增 4 张表：exam_center、exam_item、exam_order（项目 ID 快照）、exam_item_result。
- 闭环：核保员创建体检单（锁定 EXAM_REQUIRED，同案禁止并发未完成单）→ 机构录入（限本机构、项目须属本单）→ 案件重评 → 单 DONE。
- admin 机构/项目字典；案件详情含体检单明细；初始化脚本预置演示体检中心并关联 examcenter01。

过程中解决的问题（测试驱动发现）：
1. 体检回流重评再次命中"高龄体检"规则形成死循环 → 引擎增加 `skip_exam` 参数。
2. 同案件可重复创建体检单 → 未完成单校验。

测试：后端 52 用例全部通过（新增 10 个）。

## 11. 手动测试发现的缺陷与修复（共 4 个）

### 缺陷 1：投保页问卷不渲染
- **现象**：选择险种后选择框不回显、健康告知无内容、无提交按钮。
- **根因**：`ApplyView.vue` 切换险种时 `form.answers` 清空为 `{}`，模板 `v-model="form.answers[q.id].answer"` 访问 undefined 抛渲染异常。
- **修复**：切换险种时为每题预初始化 `{ answer: '', detail: '' }`。

### 缺陷 2：机构账号看不到体检单
- **现象**：已创建体检单，examcenter01 体检录入页无数据。
- **根因**：开发库在 M5 之前初始化，脚本无机构账号关联逻辑且对已有账号跳过，`exam_center_id` 为 NULL。
- **修复**：补数据关联；`init_users` 增加幂等补关联逻辑。

### 缺陷 3：待人工核保无操作按钮提示
- **现象**：待人工核保案件详情页没有出具结论按钮。
- **根因**：`canDecide` 要求核保员角色，主管账号查看（或多角色切换令牌被覆盖）时表单不渲染且无说明，易被误判为按钮缺失。
- **修复**：增加提示分支——待人工核保但非核保员登录时显示"请由核保员账号出具结论；主管请在复核中心处理复核"。

### 缺陷 4：统计导出失败（两次接力修复）
- **现象**：导出 Excel/CSV 提示"网络异常，请稍后重试"。
- **排查**：后端直连、Vite 代理、带参数、两种格式均验证正常；第一轮修复了 axios 拦截器把非 401 错误（含 403）笼统报"网络异常"的缺陷，暴露真实状态码。
- **真因（第二轮）**：`exportUrl()` 返回带 `/api/v1` 完整前缀的路径，与 axios `baseURL`（已含 `/api/v1`）拼成双前缀 `/api/v1/api/v1/stats/export` → 404。此前 curl/Node 模拟均手写正确路径未走该代码路径。
- **修复**：`exportUrl()` 改为返回相对路径；拦截器按状态码给出准确提示（403/404/422/500 各有文案）并输出诊断日志。
